# biTrader · 币安桌面交易工作台

用 Python + FastAPI 写的桌面交易软件，目前只支持币安：现货、U 本位合约、币本位合约。

> **风险提示**：加密资产交易风险高。本软件发出的每一笔委托都会到交易所，没有模拟账户。
> 建议先在币安测试网跑通全流程，再换主网小资金，并设置风控上限。
> 使用本软件造成的损失由使用者承担。

## 功能

| 模块 | 说明 |
| --- | --- |
| 交易 | K 线图、指标、画线、订单簿、市价与限价下单、交易所侧止损止盈、条件单 |
| 资产 | 交易所余额、合约持仓、权益曲线、已实现盈亏 |
| 回测 | 信号在收盘产生，在下一根开盘成交，计入手续费、滑点、杠杆、止损止盈 |
| 参数优化 | 参数网格搜索，按夏普、收益、回撤排序 |
| AI 交易 | 模型逐根 K 线复核策略信号，再决定方向和仓位。主网启动需二次确认 |
| AI 量化 | 生成或调参策略 → 回测与优化 → 人工批准 → 执行引擎按收盘 K 线调仓 |
| AI 助手 | 多周期解读并把支撑、阻力、止损画到图上。还有新闻情绪、持仓复核、收盘简报 |
| 设置 | API 凭据、主网与测试网切换、风控上限、策略插件目录 |

市场用 `spot`（现货）、`usdm`（U 本位永续）、`coinm`（币本位合约）表示。
三个市场单独选择，行情和交易都由 ccxt 封装的接口提供。

### 数量单位

| 市场 | 界面填写 | 交易所接收 | 换算 |
| --- | --- | --- | --- |
| 现货 / U 本位 | 币数量，如 `0.01 BTC` | 币数量 | 1:1（U 本位还要乘合约面值） |
| 币本位 | 币数量，如 `0.01 BTC` | 张数 | 张数 = 币数量 × 价格 ÷ 每张美元面值 |

币本位每张合约代表固定美元面值，BTCUSD 永续是 100 USD。
下单时自动向下取整为整张。不足 1 张会被拒绝，不会放大或缩小订单。
选币本位时，下单卡片会显示换算结果和预计张数。

## 安装与启动

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
python run.py
```

只启动后端，用浏览器打开：

```bash
python run_web.py
```

装成包后用命令启动：

```bash
pip install -e .
bitrader
```

数据存在 `%APPDATA%\biTrader`，可用环境变量 `BITRADER_DATA_DIR` 改位置。

```
biTrader/
├─ config.json        # 界面与风控设置，不含密钥
├─ bitrader.db        # 订单、成交、回测记录
├─ cache/klines/      # K 线缓存（Parquet）
├─ logs/              # 运行日志
└─ strategies/        # 策略插件目录
```

## API 配置

1. 在币安创建 API Key。只勾「读取」和「现货/合约交易」，不要勾提现。
2. 建议绑定 IP 白名单。
3. 打开「设置 → 币安 API 凭据」，填入并保存。凭据存进 Windows 凭据管理器，不写进 `config.json`。
4. 点「测试连接」，确认权限。

测试网和主网的 Key 分开存放，密钥环条目按 `网络:市场` 区分，互不覆盖。

第一次建议先用测试网。现货测试 Key 在 https://testnet.binance.vision 申请，
合约测试 Key 在 https://testnet.binancefuture.com 申请。填进「设置 → 币安 API 凭据 → 测试网」。
测试网的委托同样发到币安测试网撮合，只是资金是假的。

## 交易页

- K 线用 TradingView 的 lightweight-charts（Apache-2.0，v5）渲染，行情数据来自本机后端。
  图上的价格和下单、回测、AI 价位用的是同一份数据。
- 指标分主图和副图。主图有 MA、EMA、BOLL，副图有 MACD、RSI、KDJ、WR、CCI、OBV、ATR、DMI。
  每个副图指标占一个面板。参数在「指标」里改，设置存在浏览器 `localStorage` 的 `btrader.indicators.v1`。
- 画线有水平线和趋势线，可选中、拖动、删除。每个「市场 + 交易对 + 周期」存一份，
  key 是 `btrader.drawings.v1:<market>:<symbol>:<timeframe>`。
- 图上标最近 60 笔成交，用箭头表示买卖。当前持仓的开仓均价画成虚线。
- 缩放到最左会自动加载更早的 K 线，实时尾部由 `/ws/market` 推送。
- 时间轴按本机时间显示。价格小数位取交易对的 `price_precision`。

### 止损止盈

下单时可以顺带填止损、止盈。成交后立刻在交易所侧挂 reduce-only 触发单。
关掉本程序，这些挂单仍然有效。

- 已有持仓也能改挂：在「下单」卡片填好价位，点「应用到持仓」。
- 也可以在「持仓」标签页点「止损止盈」，弹窗里按百分比自动填价。
- 同一交易对只有一份保护单。重挂时先撤旧的，不会越挂越多。
- 现货没有 reduce-only 触发单。止损止盈只在合约市场可用。

### 条件单

条件单在价格跌破或涨破指定价位时才真正下单，用来等回踩进场，或预先埋伏平仓。

- 触发类型由方向决定。买单挂在现价上方是突破进场（STOP_MARKET），挂在下方是抄底进场（TAKE_PROFIT_MARKET）。卖单相反。
- 触发方向与触发价对不上时，接口直接拒绝。避免挂上去下一跳就成交。
- 现货没有条件单，界面会直接说明。请用币安自带的止盈止损。

## 回测与参数优化

- 回测页：选市场、交易对、周期，加载历史数据，设置成本和风控参数，点开始。
- 信号在收盘产生，在下一根 K 线开盘成交，所以结果不含未来数据。
- 参数优化页：给参数填候选值，如 `5,10,20`，选排序指标后运行。
- 执行引擎在交易页下方单独启动。选策略、投入比例、轮询间隔，之后每根收盘 K 线调一次仓。
- AI 量化页批准的策略会注册成正式策略，可以直接在执行引擎里选用。

## 图表代码

代码在 `web/src/chart/`。

| 文件 | 职责 |
| --- | --- |
| `TradingViewChart.tsx` | 建图、K 线与成交量、指标面板、历史分页、实时尾部、指针交互 |
| `indicators.ts` | 指标算法，纯函数。改它等于改图上的数值，动手前先和旧版输出对照 |
| `specs.ts` | 指标名称、参数、取值范围，页面和图表共用 |
| `primitives.ts` | 画线图元，用 canvas 画水平线和趋势线 |
| `adapter.ts` | 后端 K 线转成库要求的秒级时间戳，去重排序，对齐指标序列 |
| `theme.ts` | CSS 设计变量转图表主题，含本机时间刻度格式 |

改完前端要执行 `cd web` 和 `npm run build`。产物直接写进 `src/btrader/web/static`，后端不用重启。

## AI 助手

在「设置 → AI 助手」选供应商，填入 API Key。可选 DeepSeek、OpenAI 兼容接口、Anthropic、本地 Ollama。
Key 存系统密钥环，不写进 `config.json`。

以下约束是刻意的：

- 分析类功能不下单。复盘、画线、新闻情绪、收盘简报、回测过滤都不进策略循环，回测结果可复现。
- 只有「AI 交易」会下单。模型只复核策略信号的方向和仓位，每单仍要过 `AIGuard` 和 `RiskManager`。
- 数字先算好再发给模型。K 线摘要由 `btrader/ai.py` 计算，发出去的是文本，不是截图。
  从截图上读价格经常读错。
- 模型给的关键价位要和它看到的 K 线比对。落在区间外的丢弃，同类价位在 0.2% 内去重，每类最多 3 条。
- 回测过滤只看开仓点之前的 K 线。调用失败或回答读不懂时保留该笔交易，
  避免出现「因为超时所以策略变好」。
- 持仓和盈亏默认不外发。要打开「允许把持仓和盈亏发给模型」开关才会出现在请求里。
- 每日调用上限默认 300 次。结果按 K 线缓存，调用记录写到 `logs/ai-audit.jsonl`。
  上限用完后调用直接失败。
- 请求带客户端标识。部分 OpenAI 兼容中转站和 Cloudflare 防火墙会拦 Python `urllib` 的默认
  User-Agent，返回 HTTP 403 和 `error code: 1010`。`llm.py` 统一发送 `biTrader` 的
  User-Agent 和 `Accept: application/json`。遇到这个错误会提示是防火墙拦截。
- 收盘简报在独立线程生成，队列满就丢弃。简报迟到没有价值，交易循环不能被它拖慢。

## AI 交易与 AI 量化

交易页底部有两个面板。两者共用同一个交易所账户，所以互斥运行。
执行引擎在跑时启动 AI 交易会返回 409，反过来也一样。

| 面板 | 做什么 | 约束 |
| --- | --- | --- |
| AI 交易 | 策略给方向，模型复核后逐笔决定开平仓和金额，按 `poll_sec` 轮询 | 只能顺策略方向。置信度、单笔上限、总持仓上限、价格漂移、冷却、当日决策次数都在 `AIGuard` 里。「决策一次」只跑一轮，不留下轮询线程 |
| AI 量化 | 生成或调参策略、回测与优化、人工批准、部署执行（真实下单） | 部署前强制回测，要求正收益且有成交。批准不等于自动注册。执行引擎按收盘 K 线调仓 |

两个面板的开关、审计、急停都在页面上。每轮决策记在 `logs/ai-trade-audit.jsonl`，被拒绝的原因也记。
点急停会同时打开全局风控开关，并停掉两个引擎。

## 策略插件

打开「设置 → 策略插件」里的目录，放入 `.py` 文件。最小模板：

```python
import pandas as pd
from btrader.strategy.base import Strategy, IntParam


class MyStrategy(Strategy):
    key = "my_strategy"
    name = "我的策略"
    params_spec = [IntParam("period", "均线周期", 20, 5, 200)]

    def generate(self, df: pd.DataFrame, params: dict) -> pd.DataFrame:
        ma = df["close"].rolling(params["period"]).mean()
        target = (df["close"] > ma).astype(float)      # 1.0 做多，0.0 空仓，-1.0 做空
        return pd.DataFrame({"target": target}, index=df.index)
```

完整示例见 `strategies/example_strategy.py`。
策略是本机的 Python 代码，权限和本程序相同。只运行自己信任的策略。

### 改策略名

回测页「编辑源码」面板里有重命名按钮，会同时改文件名、`key` 和显示名。

- 旧文件删除，新文件写入，注册表重新加载。回测记录是快照，不跟着改名。
- 内置策略只读。先「复制为新策略」再改名。
- 目标 `key` 已存在时拒绝改名。
- 自动交易或 AI 交易正在用这个策略时返回 409。先停引擎。

### 回测候选策略

AI 生成的候选策略放在 `%APPDATA%/biTrader/strategies/candidates/`，批准前就能回测。

- 回测页的策略下拉多一个「候选策略（未注册）」分组。选中后按 `cand:<id>` 回测。
- 后台用临时目录和独立注册表加载候选，正式策略列表不会多出未批准的文件。
- 参数用源码里的默认值，没有参数表单。结果写回候选的 `backtest` 字段。
- 批准后候选才变成正式策略，之后可以正常调参。

## 风控

手动下单和自动下单都要过 `RiskManager`。

- 单笔最大金额、单品种最大持仓、最大杠杆。
- 当日最大亏损、当日最大交易次数、连续亏损熔断。
- 主网下单要二次确认。测试网不需要。
- 全局急停开关。

风控状态显示在界面顶部和设置页。被拒绝的订单会在界面提示原因。

## 微信通知

一条企业微信群机器人地址，直接发。不装网关，不起 Node，不需要公网 IP。

1. 在企业微信群里加一个群机器人，复制它的地址。
2. 打开「设置 → 企业微信通知」，把地址粘进 Webhook 地址，点「发送测试」。
   收到测试消息就说明通了。
3. 按需要关掉不想收的事件。成交、保护单、风控熔断、风险提示、任务启停都能单独关。

### 发到别的系统

地址不限于企业微信。填任何接受 JSON 的地址都行，程序按「消息格式」这一项决定发什么：

| 消息格式 | 发出去的请求体 |
|---|---|
| 自动判断 | 地址里有 `cgi-bin/webhook/send` 就按企业微信群机器人发 markdown，其它地址发 `{"title", "content"}` |
| 企业微信群机器人（markdown / 纯文本） | `{"msgtype": "markdown" 或 "text", ...}` |
| 自定义模板 | 你自己写的 JSON，用 `{title}` 和 `{content}` 占位 |

地址里有鉴权参数就不用管请求头；要用 token 的，在「自定义请求头」里每行写一个 `名称: 值`。

### 发不出去的时候

- 连续三次失败就先停发五分钟，免得每条消息都在等超时。
- 失败的消息写进 `notify-spool.jsonl`，通道恢复后自动补发，开头标【补发】。
- 超过六小时的消息直接丢掉：那时候它已经不是新闻了。
- 设置页会显示上次失败的原因、暂存了几条、还要暂停多少秒。

## 项目结构

```
src/btrader/
├─ core/          配置、凭据、数据模型、指标、SQLite 存储
├─ exchange/      ccxt 封装、K 线缓存、交易对
├─ strategy/      策略基类、插件加载、内置策略
├─ backtest/      回测引擎、参数网格搜索
├─ engine/        风控、账户快照、下单、AI 交易、执行引擎
├─ ai.py          提示词与解析：K 线摘要、价位校验、回测复核、简报
├─ llm.py         模型调用、密钥环、缓存、审计日志
└─ web/           FastAPI 后端、行情 WebSocket、前端静态资源
```
